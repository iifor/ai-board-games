# 对局剧本导入

在后台「对局管理」页点击「导入对局」，直接打开弹窗。点击「上传对局文件」选择文件，TXT、MD、DOCX 在解析前选择狼人杀或辩论赛，JSON 自动读取文件里的玩法。「查看模板」可在弹窗内切换两个玩法的 JSON 模板和完整示例。

校对后点击「完成导入」，保存并发布对局，关闭弹窗并显示来源为「导入」的对局记录。后台没有单独的导入记录或保存草稿入口。保存与发布接口仍分两步执行，发布失败时在当前弹窗中重试会复用已保存的版本。关闭有未保存内容的弹窗时需确认放弃，刷新前也会提示。

## 原文校对

- TXT、Markdown 使用 UTF-8。DOCX 从正文读取段落和表格，表格可分为发言人和台词两列。文件上限 4 MiB，Word 正文解压上限 6 MiB。
- 用「玩家3号：阿青」声明座位和姓名。「第三天」「第1夜」「第二轮」开始新阶段。「3号：……」「正方二辩：……」「评委：……」标记发言。下一段未标明新发言人时延续当前台词。用明确的发言人或阶段标题区分旁白和台词。
- 「3号：我是预言家，昨晚验了5号」整句作为发言。「预言家3号查验5号，查验结果为好人。」作为技能记录。「狼人选择刀6号」「女巫救下6号」仅记录行动。「6号出局」才改变存活状态。
- 点击时间线条目定位原文。可以更正事件、发言人、目标、可见范围和顺序。阵容与对局设置可调整座号、辩位、绑定、辩题和结果。忽略项保留原文，待处理项需要先校对或忽略才能完成导入。
- 勾选原文并选择后台模型后可请求 AI 辅助识别。发送内容包括选中段落、玩法和剧本阵容，管理员确认采用后才写入编辑中的时间线。
- 「从此处试播」在当前事件的座位状态开始静音播放。发布保存当前校对版本，观众从历史中的「导入回放」进入。文件没有结果时播放到最后显示「回放结束」。

## JSON v1

必填字段为 `version: 1`、`gameKey`（`werewolf` 或 `debate`）、`title`、`players` 和 `events`。每名玩家填写 `seat` 和 `name`，可选 `role`、`team`、`position` 和后台 `playerId`。辩论阵营为 `pro`、`con`、`judge`。可用 `topic` 提供 `title`、`pro`、`con`。可用 `result` 提供 `winner`、`winnerLabel`、`summary` 和座号 `mvp`。

事件按数组顺序播放，每条填写 `kind` 和 `text`。对局片段允许省略终局。

| kind | 补充字段 | 作用 |
| --- | --- | --- |
| phase | round、phaseId 可选 | 更新轮次和阶段 |
| speech、judgement | seat | 玩家发言、评委点评 |
| narration | | 主持播报 |
| inspect | seat、target、value | 查验和结果，仅上帝视角可见为默认值 |
| attack、save、poison | target，seat 可选 | 狼刀、救人、毒药，默认仅上帝视角 |
| eliminate、sheriff | target | 公开出局或警徽转移 |
| reveal | target、value | 从该事件开始公开身份 |
| pending、ignored | | 人工校对或明确略过 |

`visibility` 可选 `public` 或 `spectator`。公开状态变化必须在公开事件中记录。玩家视角使用舞台已有的过滤规则。绑定的玩家提供头像、立绘和座位音色，剧本姓名用于显示。无绑定时使用默认立绘，缺少云端音色时沿用浏览器朗读。
