# C 端（packages/client）

云端语音不可用而退回浏览器朗读时，`speak` 使用共享的 `stripSpeechTags` 移除 `[冷静]`、`【愤怒】` 等已登记情绪和控制标签，只朗读正文。只含标签的内容直接结束朗读。舞台中央发言、字幕栏、底部逐句字幕及其读屏文本都使用同一解析器清理标签，支持 `[停顿]`、`【停顿】` 两种括号。带时间戳字幕也在展示时清理，兼容旧缓存且不更改时间轴。普通内容如 `[3号]`、`[查杀]`、`【投票】`、`【调试】` 保留。发言记录侧栏（`EventFeed`）和座位弹层的发言汇总（`speechesOfSeat`）展示时同样清理标签；对局原文（日志、后台、回放数据）保留原始标签。

历史列表通过 `importTitle` 标记导入回放。`/import-preview` 在后台试播框内使用相同舞台，接收指定后台源发来的临时时间线。分开部署时设置 `VITE_ADMIN_APP_URL`。见[对局剧本导入](./replay-import.md)。

真实对局的选人列表只显示已启用且绑定模型的玩家。开发模式可在空列表时生成当局临时玩家。

### 舞台灯光、技能和视角

狼人杀入夜、公开叫号及等待下一条事件时，桌心显示当夜的月亮与流云。叫号时顶部显示当晚夜数与法官口令，桌心泛起一圈光晕，座位不会因公开叫号而亮起。有权观看的发言、行动与结算按事件正常播放，天亮即撤去夜景。动效跟随暂停和倍速，开启减少动态效果时显示静态月亮。夜景不另占播放时长。法官私讯在字幕和记录里标注接收者；丘比特情侣关系通知由后台告知相关玩家，服务端播放流跳过，不进入前台字幕、记录、技能反馈或语音。连线动作及已知情侣标记保留。

狼人杀玩家发言时，原座位显示暖白色锥形聚光灯和脚下光圈，人物亮起，其他玩家形象稍微压暗。灯光随发言座位切换，主持播报和非发言阶段收起；遗言也照亮对应玩家。灯光为纯装饰，不改变座位尺寸、角色配色或鼠标悬浮范围。减少动态效果时保留静态灯光。辩论赛桌面左右各展示 2×2 的完整人物，头顶辩位、脚下编号，中央保留当前发言人的大立绘和文字；评委人物在中央下方。正方青蓝、反方红、评委金色，发言席位显示对应阵营的聚光灯，其他人物略微压暗。两种布局的发言座位都带有“正在发言”的读屏提示。狼人杀按真实行动、计票结果和结算事件播放技能图形；目标座位同时响应，放弃行动不会出现命中效果。减少动态效果时保留图形、动作名与座位。手机辩论保留紧凑头像，逐句字幕随页面排在阵容下方，避免覆盖立场和头像。

前台统一隐藏页面和组件内部的滚动条，不保留滚动条占位。滚轮、触屏与键盘仍可滚动查看内容，发言记录的自动跟随和手动回看保持原有行为。

播放栏可切换上帝视角与随机玩家。狼人杀隐藏其他人的非公开身份；辩论赛的正反方和评委席是公开信息。随机座位在同一标签页的同一局固定；切换视角会终止当前音频，从当前事件附近用新的服务器投影续播。切换后的记录自该位置重新累积，从头回放可查看该视角的全局记录。

## 路由

C 端通过 `POST /api/toc/matches` 开始游戏，服务端在创建时锁定本局模板原文，客户端继续接收对局概要。

本地开发的开局页提供「生成 N 名模拟玩家并开局」。人数取所选板子或游戏的最少合法人数，保留当前辩题与板子。玩家库为空时可直接使用这个入口，创建后进入正常播放舞台。正式构建只展示真实玩家开局。

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` | `LobbyPage` | 头图（入口按钮 + 最近一局）、游戏目录（`GET /api/toc/games`）、最近对局（`GET /api/toc/matches`）。目录与历史分开加载：历史失败只在最近对局区显示错误与重试（头图条幅显示"暂时拉不到"），不冒充"还没有完成的对局"，头图与目录照常 |
| `/play/:gameKey` | `SetupPage` | 狼人杀在选人前展示可搜索的模式列表与当前模式的角色构成，玩家按座号就座，「按序补满」沿候选列表补位。辩论赛侧栏按目录的公开分组展示正方、反方和评委，「随机补满」抽取空位人选。点已选卡或座位可离席，侧栏可展开辩题或本地模拟开局。底栏按当前人数提示是否可开局。终局可带入同一模式与玩家再开一局。 |
| `/matches/:matchId` | `StagePage` | 对局舞台；实时观看与回放是同一页面、同一条播放流 |
| `/history` | `HistoryPage` | 已完成的公开对局 |

路由用 react-router 7（`createBrowserRouter`），`app/` 只做路由与外层布局；舞台路由全屏铺满、不显示导航。

## 视觉与动效

沿用旧版的"直播间"风格：深海蓝画布、玻璃面板（`.glass-panel`）、金色品牌色，游戏强调色由 `data-game` 覆盖（辩论赛青色、狼人杀紫色），令牌都在 `styles/global.css`。玩家海报（`public/player-posters`、`public/player-poster-cutouts`）与舞台背景（`public/stage/*.png`）取自旧版素材；选人卡展示当前绑定模型的显示名和玩家人设。新对局按玩家的固定立绘标识取图，旧回放沿用已有形象。

动效用 CSS 为主、Web Animations API 为辅（无动画库）。`prefers-reduced-motion` 下 CSS 动画由 `global.css` 统一关闭（组件 CSS 另把自己的错峰延迟归零，避免空白），JS 动效在 `lobby/animations.ts` 里判断后直接不动：
- 大厅：头图各元素与游戏卡片错峰淡入上浮（`.ui-fade-up` + `--i`，卡片排在头图之后）；游戏卡片悬停 / 键盘聚焦（`:focus-within`）是同一套状态：上浮、一道扫光（`::after` 动画一次）、图标亮起游戏强调色，说明与标签不动；"最近一局"卡片悬停上浮、背景缓慢放大并随指针轻微视差（`useParallax` 把偏移写成 `--px` / `--py`，纯计算 `parallaxOffset`），有最近一局时条幅显示胜方与时间，右侧"去开一局 → / 回放 →"做成胶囊按钮。没有最近对局时，「去开一局」直达默认玩法配置页。大厅重试会重新加载失败的最近对局。板子搜索显示匹配数，方向键可在可见结果中切换，模拟开局区同步显示所选板子及开局人数。
- 开局选人时，`useSeatFlights` 让头像从卡片飞到对应座位。两种补满方式都按新座号错峰入座，清空时按座号淡出。切换狼人杀模式会同时更新角色标签、席位数和底栏人数提示；如果超员，多出的座位标红并允许逐一取消。
- 历史：行错峰淡入上浮（错峰只排前 10 行），悬停 / 聚焦上浮并点亮右侧"回放 →"。
- 舞台：狼人杀昼夜背景按 `view.extra.period` 圆形揭开切换（`StageBackdrop`）；进入新阶段时大标题横扫而过（`PhaseBanner`）；发言者座位亮起扩散光环、立绘站在圆桌中央（`SpeakerSpotlight`，主持人也站在这里；行动事件如开枪、自爆由当事座位站到中央），没有立绘的玩家换成"发言者大卡"（`SpeakerCard`：大头像 + 名字 + 座位号 + 观众可见的身份 / 阵营，光环取阵营色 `--team-color`，进场同样用 `spotlight-in`；主持人始终用立绘）；夜晚没有在行动的存活座位闭眼（`SeatCard` 的 `seat-card-asleep`：人物略微压暗；正在行动的座位亮着发言光环，出局者保持出局样式；天亮靠座位卡既有的 opacity / filter 过渡交叉淡入）；字幕栏从下方滑入、文字从左向右揭开，进度条跟随真实播放进度（`SubtitleBar` + `SubtitleProgress`）；计票时选票从投票者座位沿弧线飞到目标座位（`BallotFlight`，Web Animations API：错峰起飞、落地时目标卡片一弹，弃票在原座位闪烁消失；时长 = 这段停留时长的六成、封顶 3 秒，随倍速缩放，没有当前段时 1.2 秒，纯计算在 `animation/ballotFlight.ts`），飞完票板的票数条才依次长出、当选者金色高亮（`VoteBoard` 的 `delayMs`；只有登记了 `ballotFlight` 的布局会飞，减少动效时不飞、票板立刻长条）；出局座位变灰并盖"出局"戳；终局结果以对话框弹出，展示带座号的 MVP 圆形头像（配置头像优先，其次为内置肖像，缺图时显示通用人像）、按阵营逐行揭示的阵容（`--i` 全表行号错峰；胜负按 `result.winners` 逐座位判断，旧结果退回阵营等于获胜方：整组获胜的阵营在最后一行亮出后扫过一道光并留下金色光晕，组内只有部分座位获胜时这些行用金色标出「获胜」）与"同样阵容再来一局 / 从头回放"（`ResultPanel`、`ResultRoster`），可关闭后再用"查看结果"打开。

通用小部件：`components/Avatar`（座位与 MVP 使用 portrait 优先读取配置头像，再匹配内置肖像；`round` 圆形 / `figure` 立绘，座位卡、字幕栏、终局 MVP、选人卡片都用它）；胶囊标签统一用 `global.css` 的 `.ui-pill`（修饰类 `-accent` / `-brand` / `-outline` / `-soft`，使用处只覆盖颜色）；"游戏 · 板子"用 `@battle/shared` 的 `formatMatchTitle`（与 B 端共用），胜方、日期时间用 `utils/format.ts`（`formatWinner` / `formatDateTime`，24 小时制）。样式不用 `!important`：需要盖过通用规则时提高选择器具体度（如 `.playback-rail .playback-toggle:hover`），需要被媒体查询改写的值走自定义属性而不是内联样式（终局阵容列数 `--roster-columns`）；只有 `prefers-reduced-motion` 的全局关动效例外。

## 播放

发言失败时按该座位及原频道播放「过~」。失败的行动显示放弃，计票面板列出请求失败而弃票的座位。

辩论人物席位使用 `SeatCard` 的 `figure` 变体：桌面立绘和手机紧凑头像共用同一个悬浮/键盘资料入口。`RingSeatFigure.css` 承载两种游戏共用的形象、编号站台和姓名样式，`SeatCardFigure.css` 管理辩论人物及响应式显示。人物素材、中央发言、脚本化调试静音及视角投影均沿用现有模块。验收与文件职责见 [辩论人物布局验收](operations/debate-figures-qa-20261108.md)。

### 狼人杀技能交互

- `animation/skillCue` / `skillResults` 将当前可见的行动、计票、揭示与结算事件转换为施法和结果提示。查验文字仅来自事件的 `text`；普通预言家不会读取座位的真实身份补全结果。狐狸、占卜范围只显示一份汇总反馈。
- `skillTypes` 定义前端提示、座位坐标和状态标记；`skillPlan` 复用选票的贝塞尔采样，分别规划直射、药剂弧线、双向换号、学习返回、反噬与幻象承伤的方向。自我确认不当作自我攻击；伤亡、解药和守护是否生效只取真实结算。
- `CircleLayout` 的 `useSeatAnchors` 测量实际立绘位置，兼容桌面椭圆、缩放及手机网格。`SkillInteraction` 组合 `SkillRoutes` / `SkillTargets`，轨迹位于人物下层，目标响应和结果浮现位于人物前，发言、记录、字幕与 HUD 保持在上层。座位不移动，不新增玩家边框。
- 技能包括斩击、决斗、盾、治疗、毒雾、查验、枪击、羁绊、封印、梦境、冰冻、技能卡、转化、爆破、警徽与身份揭示。颜色、图形和动势共同区分技能；`SeatSkillMarks` 展示当前视角已知的守护、封印、冰冻、羁绊、负伤和剩余资源，短期状态按昼夜边界清理，出局清理人物标记。翻牌和羁绊额外显示人物身后的半透明大卡牌、大锁链，前方角标增大至 28px 并显示「已翻牌」或关系文字。丘比特连线的情侣双方标明已知配对座号；其他羁绊保持通用标识。大图形置于人物下层，不拦截鼠标，不改变座位尺寸或动效坐标；尾巴和命数维持紧凑样式。
- `useSkillMotion` 使用一条片段时钟管理 WAAPI 动画，实时响应倍速；重排保留已播放时间，跳段/卸载清理。减少动态效果时保留静态落点和结果。`skillTiming` 为普通技能保留 2.2 秒、结果 1.8 秒、连锁最多 2.8 秒的基础展示时间，并与语音并行；独立计时器不覆盖语音进度。上警、退水仍使用原来的短动效。
- 脚本化调试局默认静音，便于反复验证动画；生成和播放调试局均不调用真实模型或云端 TTS。
- `skillInteractions.test` 使用全部 31 个板子的真实规则事件验证坐标与轨迹，并覆盖查验隐私、范围汇总、守护与解药组合、幻象承伤及方向；`skillTiming.test` 验证变速与中止时计时器清理。浏览器布局、实际画面与完整调试局另做验收。
- 本轮验收范围、文件职责及本地证据清单见 [技能交互验收](operations/skill-interactions-qa-20261108.md)。

- `useMatchStream(matchId)`：连接 `WS /api/toc/ws/matches/:id`（逻辑在 `stream/connection.ts` 的 `MatchStreamConnection`），连上即发 `hello`，按 seq 去重地累积事件；收到 `end` / `error` / `status: failed` 后不再重连。
  - 续播与丢失的 ack：`hello.afterSeq` 是**最后播放完的 seq**（不是最后收到的），服务端从它之后续推并把它当作确认；所以断线期间播完的事件虽然 ack 发不出去，重连时也会由 hello 一并补上，后台"观众确认"不会少一个。
  - 重连策略：断开后按 1、2、4、8、15 秒退避重连（步长确定，无抖动；`constants.ts` 的 `RECONNECT_*`），服务端对 hello 的任何回应都清零失败计数；连续失败 `MAX_CONNECT_FAILURES`（6）次后放弃自动重连，`connection` 变为 `lost`、`error` 为"连接中断，请刷新重试"，舞台顶部出现带"重试"的错误面板（`StageError`），`retry()` 清零计数立即重连。连接状态 `connecting / open / lost / closed` 由 HUD 显示为 连接中 / LIVE / 连接中断 / 已结束。
- `usePlayback(items, ack, options)`：依次播放事件（`playback/media.ts` 的 `present`）——有服务端音频播音频；否则 `@battle/shared` 的 `speechOf(event)` 不为 null 的事件用浏览器朗读 `speechOf(event).text`（发言、评委判定 + 点评、主持播报、揭示、行动、终局总结；行动由主持人声音读，字幕仍归到行动者座位）；其余按字数停留。**每个事件播放完才 ack**，服务端据此推进下一个事件，因此观众暂停时 AI 也会在领先若干事件后停止生成。暂停只阻止开始新的事件；只有卸载页面或切换对局时才中止正在播放的事件。
- 每段内容由一个 `SegmentControl`（`playback/segment.ts`）承载实时控制与进度：倍速立即作用于音频 `playbackRate` 与停留计时器（按已走过的比例重排剩余时间）；浏览器朗读的语速只能在开始前设定，倍速改变要到下一段才生效。静音立即停掉正在播的音频 / 朗读，剩余部分按字数停留走完；取消静音只对下一段生效。播放看门狗（`constants.ts`）：浏览器朗读超过预计时长的 2 倍再加 5 秒仍未结束（Chrome 偶发不触发 `onend`，朗读期间另外持有 `SpeechSynthesisUtterance` 引用以防被回收）按播完处理；服务端音频连续 8 秒没有播放进度（缓冲卡死却不报错）改为按剩余比例停留。否则这一段永远不 ack，ack 节奏的对局会停住。
- 停留时长 `displayDuration` 按字数估算（160ms / 字，最少 0.9 秒，不封顶），倍速缩短；静音时全部按停留时长展示。
- 字幕进度条（`SubtitleProgress`）：音频在播时跟随音频元素 `timeupdate` 报告的实际进度；朗读与停留按同一个 `displayDuration` 线性推进（CSS 动画，倍速改变时从当前比例重新起算）。只有字幕栏订阅进度，舞台其它部分不随进度重渲染。
- `playback/describe.ts` 把舞台事件映射为字幕。朗读内容统一取自 `speechOf`，包括随阶段标题展示的法官台词。夜间叫号的声音和字幕都归主持人。狼人杀白天的警长票和放逐票由投票面板展示，放逐最高票标为「得票最高」。主字幕随法官公布实际结果，普通放逐与遗言邀请合播一次。

## 舞台分层

阶段切换横幅显示在页面顶部中央，使用紧凑横条；861–1200px 窗口将其放在顶部控制行下方，避免遮住 HUD 与播放按钮。手机继续通过顶部状态条显示当前阶段。

狼人杀上警和退水选择由 `animation/sheriffSignup` 从已播放的公开事件计算，当前选择通过 `SheriffSignup` 在对应人物上播放短动效（上警为金色升光，不上警为灰色淡出，退水为灰光下落并短暂暗淡人物，继续竞选为金色亮起），每次停留 400ms 并随倍速缩短。上警座位头顶显示警徽图标，保留至本次警长竞选结算；退水选择出现时立即移除，继续竞选则保留。竞选发言、投票和 PK 期间保持。两种环节的逐人选择不上舞台中央和逐句字幕，旧回放已缓存的选择语音也忽略，完整选择仍保存在对局记录中。竞选发言及最终当选播报正常播放。

`StagePage` 将座位与舞台中央放在同一层，HUD、控制条和结果对话框位于上方。狼人杀在玩家发言时使用桌心轮播，主持播报和行动内容使用底部字幕，空档自动收起。顶部显示模式和当前阶段，夜间阶段经过可在「记录」的「全部」中回看。倍速通过单个选择框切换，辩论赛的文字在舞台中央。桌面左上角提供「返回大厅」「对局记录」和「发言记录」。对局记录在左侧，仅展示阶段、主持播报、行动与结算等本局流程事件，排除玩家发言和点评；发言记录在右侧，按播放顺序保留各玩家已播完的发言与点评，显示发言人。两块面板独立开关（`hooks/useRecordPanels`），L 快捷键切换左侧对局记录，右侧通过自己的按钮开关。打开舞台时按视口宽度决定是否默认展开（`utils.recordPanelsOpenByDefault`：圆桌 ≥1280px、辩论赛 ≥1700px，见 `constants.RECORD_PANELS_MIN_WIDTH`），窄窗口默认收起。展开的面板占用舞台两侧的位置而不是浮在座位上：圆桌舞台按 `--history-left` / `--history-right` 让位，辩论赛的两块面板是页面网格的首尾两列（收起时宽度为 0）。面板顶部在 HUD 之下（`--stage-history-top`）、底部让出字幕，使用 86% 不透明的深色实底和模糊，正文保持 12–14px，宽度为 clamp(260px,20vw,400px)。窄屏（≤860px）时两块面板是底部抽屉，一次只开一个。历史面板不替换中央舞台。中央发言卡贴在立绘下部，深色实底，人物的脸和上半身不被文字遮住；窄屏的底部字幕铺满宽度并带渐变底色。圆桌和字幕始终居中。窄屏时狼人杀先显示播放控制与字幕，再显示桌心和按座号排列的人物。终局对话框可滚动查看阵容，播放完毕后暂停键停用。

各层共用的尺寸定义在 `StagePage.css` 的 `.stage-shell` 自定义属性上：`--stage-rail-width`（控制条最大宽度，HUD 据此让位，两者不会重叠）、`--stage-subtitle-max-height`（字幕栏最大高度，舞台底部据此留白，字幕不会盖住座位）、`--stage-gutter`。

终局：`ResultPanel` 是 `role="dialog"` + `aria-modal` 的对话框，打开时焦点移入、Tab 在内部循环、Escape 或关闭按钮关闭、关闭后焦点还回（`hooks/useDialogFocus`）；关闭后舞台保持终局状态（座位与对局记录都可达），底部出现"查看结果"可再打开（`useResultDialog`）。对话框根元素就是遮罩，卡片是它唯一的网格项：列轨道给定为 `minmax(0, 1fr)`、`align-content: safe center`、卡片 `width: min(1000px, 100%)`，所以卡片永远居中于视口且不会比视口减边距宽（隐式 auto 轨道会被长摘要撑到比视口宽、再居中就把卡片推出左边缘——这是旧版"卡片被切掉"的原因）。播完后字幕停在最后一段。

交互：键盘快捷键由 `hooks/useStageShortcuts` 监听 `window` 的 keydown——空格 暂停 / 继续、← / → 倍速（控制条提供的 1 / 1.25 / 1.5 / 2 / 3 档，到头不变）、M 静音、L 切换对局记录、R 查看 / 关闭结果（只在有结果时响应）；键 → 动作是纯函数 `utils.shortcutActionOf`，选项变化是 `applyShortcut` / `stepSpeed`。按住 Ctrl / Meta / Alt、焦点在输入框 / 文本域 / 下拉框 / 可编辑区域时一律不响应；焦点在按钮上时空格交给按钮自己（保留按钮的原生激活），其余情况空格 `preventDefault` 不滚动页面；长按的重复事件只拦默认行为不重复切换；Escape 不归快捷键（终局对话框与座位弹层各自处理）。控制条按钮与"查看结果"用 `title` / `aria-keyshortcuts` 标出快捷键（文案在 `constants.SHORTCUT_HINTS`）。鼠标悬浮或键盘聚焦座位时，`SeatPopover` 展示该座位的头像、可见身份、阵营、存活状态和已播放的发言。资料卡贴近座位，右侧放不下时翻到左侧，窄屏贴底。指针可以跨过座位与卡片之间的间隙进入记录区滚动。离开两者后收起，聚焦座位时按 ↓ 可进入记录，Escape 收起资料。

读屏：播报字幕与当前发言分别使用礼貌级 live region，同一时间只呈现一处；历史发言可以回读，阶段横幅、票板、控制条状态只展示不播报。小字颜色 `--ui-text-dim` 在舞台底色与玻璃面板上的对比度 ≥ 5:1。

## 布局

`layouts/registry.tsx` 把游戏声明的 `presentation.layout` 映射到 `{ Component, ballotFlight }`（舞台页从对局概要的 `layout` 字段取值，不依赖游戏目录接口；`ballotFlight` 说明布局有座位坐标、会播选票飞行，舞台据此让票板等飞完再长条）。`LayoutProps`：`center` 是舞台中央内容（辩论中央文字播报或记录、狼人杀票板或立绘等），`badges` 是舞台算出的座位徽章，`period` 是昼夜（夜晚未行动的存活座位闭眼，`utils.ts` 的 `isAsleep`），`vote` 是正在播的计票（选票、弃票与时间安排 `VoteFlight`，由 `Stage` 用当前段的倍速算出）：

- `versus`（辩论赛）按辩位排列两侧的大头像卡，评委在下方。卡片、中央发言者和座位资料优先用玩家配置的头像，模拟玩家按编号复用固定肖像。辩题在舞台顶部保持单行，窄屏滚动时吸顶。标题按实际文字宽度缩小，最小 16px，过长时支持横向滚动查看全文。双方立场分别显示在队名与首张座位卡之间，玩家发言与评委点评使用共享的 `SpeechCarousel`，其余播报与计票由 `DebateBroadcast` 展示。辩手发言和评委点评时，对应玩家的透明立绘作为中央文字背景，缺少立绘时使用配置头像。主持播报和计票使用舞台原景。默认显示播报，点「记录」或按 L 在原位查看和筛选已播内容，包含正在播放的一段；收起后回到当前进度。窄屏依次显示辩题、播放控件、播报、双方队伍和评委席。
- `circle`（狼人杀）：1 号位在正上方，按座号顺时针排列。每个座位展示玩家立绘和名牌。形象按玩家的立绘标识或模拟编号匹配，其次使用配置头像，缺图时显示通用剪影。造型与游戏身份独立。桌心在玩家发言时显示与辩论赛相同的轮播，其他事件按播放游标切换主持人、技能、票板或记录。默认模拟玩家以座号标识，模型玩家显示座号与开局时的模型名；只有当前视角可见的身份才加入名牌。顶部模式名优先使用对局概要，缺失时由 `view.extra.board` 补足。警长座位和昼夜取自 `view.extra.sheriff`、`view.extra.period`。
  两种布局的玩家发言使用当前发言者的立绘作背景，按舞台空间等比缩放并完整展示。人物容器透明，直接透出舞台原景；仅聊天框保留一层底色，不叠加外围渐变和遮罩。发言区域宽度上限 1200px。狼人杀消息框按座位间距扩展，宽度上限 72rem，文字轨道占发言区域高度的 94%。辩论赛消息框宽度上限 64rem，文字轨道占 88%，底色不透明度从上至下为 28%–40%，当前文字不透明度为 85%。中央聊天框仅显示当前发言并垂直居中，流程概览与发言历史分别在左右两侧独立滚动。序号与玩家名使用可见阵营色，正文白色，段落内部完整换行。进度条位于聊天框下方。长发言优先利用更高的中央区域，仍放不下时由 `useFitSpeech` 按真实换行高度缩小字号，使整段在同一屏展示；不自动滚动，也不提供内部滚动。窗口变化和字体就绪后重新测量，换人或换段恢复合适字号。圆桌发言框始终避让座位，进度条仍正常播放。

常规舞台的玩家发言、评委点评和主持播报都保留底部逐句字幕，中央完整发言与底部当前一句同时展示。`StagePage` 不按玩家发言类型隐藏 `SentenceCaptions`；后台导入试播使用同一字幕组件。玩家发言的读屏播报仍由中央发言区负责，底部不重复播报。字幕容器宽度统一为 80vw，整行文字居中，说话人与首行正文按文字基线对齐，长句自动换行。背景透明，不显示底色和面板投影，以文字阴影保持可读性。Azure 音频的 `audio.captions` 提供同次合成的真实毫秒时间轴，`useSentenceCaption` 按音频元素的 `currentTime` 选句；倍速不缩放时间戳，停顿间保留上一句，下一句只在起读时间到达后出现。`captionTextChunks` 在共享包统一句子与长句切分。旧音频、其他供应商或没有有效时间轴时仍按句长与播放比例估算；静音和本地朗读使用播放器的计时进度。逐句字幕移除朗读控制标签，复用当前视角的正文，不额外暴露身份信息。桌面在舞台底部留出字幕位置，窄屏固定在视口底部；字幕自身不滚动。原有暂停行为仍为当前段播完后暂停下一段。
  桌面布局由 `fitRingBox` 按舞台高度和 1.7 的宽高比计算，上限为舞台宽度；桌面舞台两侧按记录面板宽度加 16px 间隔留位，圆桌自然收圆，4 号和 10 号随整体几何向内收。`ringGeometry` 将 144 × 184 的人物座位沿椭圆弧长均分，随可用空间调整大小。`seatAnchors` 将相同的座位中心提供给投票动效。窄屏改为按序网格，每列至少 96px。

座位使用服务端投影的公开角色和阵营。狼人杀把角色名放在立绘头顶，座号显示在脚下站台，自定义玩家名列在站台下。好人为绿色、狼人为红色，独狼与其他特殊阵营各有配色，未公开阵营使用中性色。出局后人物置灰，站台保留已公开的阵营色。座位可用 Tab 聚焦，`LayoutProps.onSeatSelect` 与 `selectedSeat` 将当前悬浮或聚焦的座位传给舞台。

## 约定

- 前端不决定任何游戏结果，只展示服务端下发的事件与观众视图；不处理密钥。
- 终局 → 开局的"同样阵容再来一局"是跨 feature 契约：类型 `SetupInitial` 与生成函数 `rematchStateOf` 由 `features/lobby` 导出，`ResultPanel` 只用它们生成路由 state，`SetupPage` 用 `isSetupInitial` 校验。 含临时玩家的对局显示「同玩法再开一局」，沿用玩法与板子，由开局页重新配置阵容。
- 开发端口 `5173`，`/api`（含 WebSocket）代理到 `http://127.0.0.1:3100`。
- 测试（vitest，`environment: node`，无需浏览器）按主题分文件，夹具在 `game-stage/stage.fixtures.ts`：
  - `game-stage/playback.test.ts`：字幕映射与朗读选择（与 `speechOf` 一致）、展示时长、媒体播放（假 `Audio` + 假计时器：自动播放被拦截、倍速实时生效、中途静音、停留重排、朗读不结束与音频卡住时的看门狗）、`present` 选路（有音频播音频 / 行动用浏览器声音 / 公开阶段台词朗读 / 普通标题只停留 / 静音全停留）。
  - `game-stage/stream.test.ts`：退避步长；假 WebSocket + 假计时器：重连时 hello 带播放到的 seq、1/2/4/8/15 秒退避后报错与手动重试、结束后不重连、卸载取消重连。
