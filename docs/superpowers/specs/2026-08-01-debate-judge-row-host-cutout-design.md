# 辩论赛评委单行与主持人立绘设计

## 目标

在不改变辩论赛流程与数据协议的前提下，解决四位评委换行造成的舞台拥挤，并让主持播报拥有明确、克制的视觉主体。

## 设计决策

### 评委席

- 有评委时，评委席固定为一行，最多四张卡片。
- 四张卡片在中央区域内等宽分布，不允许换行。
- 昵称优先完整展示；模型名空间不足时使用单行省略。
- 没有分配评委时继续不渲染评委席，不保留空位。
- 保持现有点击查看玩家详情、发言态和 MVP 信息语义。

### 主持人立绘

- 仅在主持人发言或阶段播报时显示主持人立绘。
- 玩家或评委发言时，主持人退出舞台，由现有玩家立绘接管。
- 指定 AI 玩家担任主持人时，优先复用该玩家已有透明立绘。
- 使用默认主持人时，显示一张独立的默认主持人透明立绘。
- 默认主持人视觉定位为专业、亲和的未来赛事主持人：深色礼服、少量金色细节、正面站姿，不携带阵营色，避免偏向正方或反方。
- 立绘采用短时淡入淡出，不增加常驻动画。

## 舞台层级

从后到前依次为：

1. 舞台背景与灯光。
2. 主持人或当前发言玩家立绘。
3. 中央环节信息与评委席。
4. 字幕和操作控件。

主持人立绘不得遮挡辩题、当前环节、评委卡片或字幕。主持播报结束后立即释放中央舞台。

## 状态判定

- 当前字幕或事件的 `speakerRole` 为 `host`：显示主持人立绘。
- 存在当前玩家发言者：显示玩家立绘，不显示主持人立绘。
- 系统播报、空闲、等待开局、无可播放文本：不显示主持人立绘。
- 默认主持人资源加载失败：保持舞台为空，不显示破图或占位框。

现有主持人角色标识和游戏序列化数据已经足够，本次不新增 WebSocket 字段。

## 组件边界

- `DebateGame` 继续负责从现有播放状态判断当前发言者。
- `DebateArena` 负责在玩家立绘与主持人立绘之间互斥切换。
- `PlayerPosterSpotlight` 继续承担透明立绘展示与图片失败降级。
- Debate v2 样式负责评委单行布局、主持人立绘尺寸、位置和层级。
- 默认主持人立绘作为静态视觉资源加入现有客户端资源体系，不新增组件或依赖。

## 响应式行为

- 桌面宽屏：四张评委卡片单行等宽展示。
- 中等宽度：保持单行，收紧卡片内边距、头像和文字间距。
- 小屏：允许评委席横向滚动，不允许重新换成两行；滚动区域应保持键盘和触摸可用。
- 主持人立绘随舞台高度缩放，始终保持完整人物比例，不拉伸、不裁切。

## 无障碍

- 主持人立绘沿用现有实时播报语义，不重复朗读同一段主持人字幕。
- 装饰性立绘图片使用空替代文本；主持人身份由字幕标签表达。
- 评委卡片继续使用现有可点击控件与焦点状态。
- 尊重 `prefers-reduced-motion`，在减少动态偏好下取消淡入淡出位移。

## 验证

- 增加最小样式测试，锁定评委席不换行、四列等宽和空评委席不占位。
- 增加最小状态测试，锁定主持播报、玩家发言和系统播报三种互斥显示状态。
- 运行客户端类型检查和相关单元测试。
- 在 Debate v2 实际页面验证四位评委、无评委、指定玩家主持人、默认主持人四种状态。
- 将参考截图与实现截图按同一视口、同一状态并排比较，检查遮挡、间距、层级和文字溢出。

## 非目标

- 不修改主持人 AI 行为、声音、提示词或游戏流程。
- 不新增后端接口、数据库字段、共享类型或 WebSocket 协议。
- 不让主持人立绘常驻舞台。
- 不为评委创建新的卡片组件。
- 不改动正反方玩家席位布局。
