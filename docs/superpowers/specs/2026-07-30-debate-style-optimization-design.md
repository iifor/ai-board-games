# 辩论赛样式优化设计

## 目标

在不改变辩论流程、WebSocket 事件、数据库和 API 返回结构的前提下：

1. 修复“随机分配后出现空辩位、无法保存”的阻断问题。
2. 优化辩论赛 v2 的舞台层级、人物可读性和控制区可用性。
3. 为阵营分配补充鼠标点击和键盘可用路径，并显示明确的保存条件。

## 现状与根因

- `DebateGameV2` 复用 `DebateGame`，通过 `.debate-shell--v2` 提供视觉皮肤。
- 设置弹窗由 classic/v2 共用，现有阵营调整仅支持拖拽。
- 前端 `normalizeDebateTeamDraft` 固定取候选 ID 的前 12 个；随机分配接口会从全部候选人中随机选 12 个。候选人数为 13 时，接口可能返回前端允许集合之外的玩家，该玩家被归一化丢弃，最终留下空辩位。
- 设置弹窗只把随机分配错误写入控制台，也没有解释“保存”按钮为何不可用。

## 设计范围

### 1. 随机分配一致性

- 随机接口继续返回现有 `debateTeams` 结构，不新增 API 字段。
- 前端用接口实际返回的正方、反方、评委 ID 构造本次 12 人允许集合，再归一化队伍，避免合法随机结果被截断。
- 接口失败、响应缺失或返回不足 8 名辩手时，在弹窗内显示可见错误，不再只写控制台。
- 保存校验继续要求辩题、正反立场、正方 4 人、反方 4 人；未满足时显示缺失项。

这一步不引入新的“选手池配置”或主持人配置流程。主持人是否参与候选池属于独立产品规则，本次只修复客户端与现有接口结果不一致的问题。

### 2. 可操作的阵营分配

- 保留现有拖拽，避免重写队伍组件。
- 玩家卡和辩位改为原生按钮语义：
  - 点击或键盘选择一名观众席玩家。
  - 再点击或键盘激活目标辩位完成分配。
  - 已选玩家有清晰的视觉状态和 `aria-pressed`。
- 点击已占用辩位时沿用现有交换规则，不新增第二套分配算法。
- 观众席保留拖回能力，并为非拖拽用户提供“移回观众席”的按钮操作。

### 3. v2 舞台视觉

视觉修改只作用于 `.debate-shell--v2`，classic 保持现状：

- 保留当前深色舞台背景和透明人物剪影，不替换用户已有素材。
- 顶部直播 HUD 作为唯一一级标题；v2 中压低或移除重复的“AI 辩论赛”标题。
- 中央区域优先展示当前阶段、辩题和发言者，减少重复状态文案。
- 左右阵营席位增大人物头像与姓名区域，并同步放大当前发言光环，避免拥挤。
- 底部控制按钮最小高度为 44px；弱化文字提高对比度，确保暗色背景可读。
- 保持 1280×720 主视口不溢出；较窄视口继续使用现有响应式布局。

## 状态与错误

- 随机分配中：按钮禁用并显示“分配中…”。
- 随机分配失败：弹窗内显示错误，原队伍草稿不变。
- 队伍不完整：保存按钮禁用，并显示如“还缺正方 1 人”。
- 点击分配中：已选择的玩家保持高亮；完成分配或移回观众席后清除选择。

## 预计代码边界

- 前端：
  - `DebateTopicDialog`：随机结果边界、错误状态、选择状态、校验提示。
  - `DebatePlayerPool` / `DebateTeamBoard` / `DebateTeamSlot`：复用现有分配回调，补按钮语义和点击入口。
  - `debate-v2` 及对应辩论组件 CSS：仅做 v2 作用域内的层级、尺寸、对比度调整。
  - `debateUtils`：仅在现有纯函数无法直接覆盖随机结果集合时做最小修改。
- 后端：不修改。
- 数据库、共享类型、API 结构：不修改。
- 文档：同步更新 `docs/project-client.md` 的 v2 舞台和设置交互约定。

不新增依赖，不新增页面，不建立平行的设置组件。

## 验证

- 单元测试复现“13 个请求候选、接口返回其中任意 12 个”的场景，确认正反方各 4 人不会被归一化丢弃。
- 覆盖随机请求失败和队伍缺员提示。
- 运行客户端类型检查、构建和现有单元测试。
- 在 1280×720 运行页面验证：
  - 随机分配后可保存并进入调试模式比赛。
  - 鼠标点击和键盘都能完成阵营分配。
  - idle、设置、发言中、赛后状态无重叠或裁切。
  - 控制按钮、弱化文字和人物信息在暗色舞台上可读。

## 非目标

- 不调整 AI 辩论提示词或比赛阶段。
- 不重做 classic 辩论页面。
- 不新增主持人选择功能。
- 不修改回放、语音、结算和历史记录逻辑。
