# 管理后台登录限流设计

## 目标

防止管理后台登录接口被持续猜测，同时保持当前单 Node.js 实例部署的最小复杂度。

## 方案

- 对 `POST /api/admin/auth/login` 按“客户端 IP + 规范化用户名”维护内存失败计数。
- 同一组合在 15 分钟窗口内最多允许 5 次失败；后续请求返回 HTTP 429。
- 成功登录清除该组合的失败计数。
- 使用 Express 已配置的 `trust proxy = 1` 读取负载均衡传入的客户端 IP。
- 失败计数只保存在当前 Node.js 进程。重启会清除计数；当前 Docker Compose 单实例部署符合这一边界。
- 腾讯云 WAF 对相同路径实施 IP 级请求限流，作为应用限流的边界补充。

## 不在范围内

- 不新增数据库表、Redis 或其他外部依赖。
- 不变更登录成功响应、JWT 格式或前端登录流程。
- 不做验证码、MFA 或持久化账号锁定。

## 验证

- 单元测试覆盖：第五次失败仍可处理、第六次请求被拒绝、成功登录清除失败计数、窗口到期后恢复。
- 运行认证相关单元测试、全量单元测试、类型检查与构建。
