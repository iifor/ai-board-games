# 模型额度耗尽标记与备用模型切换设计

## 目标

当模型供应商明确返回免费额度耗尽、余额不足或欠费错误时，系统持久化标记并停用该模型，同时复用玩家已经配置的备用模型继续当前请求。管理员补充额度后，通过后台手动测试并重新启用模型。

本设计不主动抓取供应商控制台，也不估算剩余额度。供应商控制台数据存在延迟，且目前没有适用于两家供应商的稳定统一剩余额度接口；以实际推理响应作为最终可用性信号更可靠。

## 现有能力

- `packages/server/modules/llm/service.ts` 已区分额度/欠费错误与普通限流。
- 明确额度错误会将模型设为 `enabled = 0`，并加入当前进程的禁用集合。
- `callWithModelFallback()` 会在主模型失败后调用玩家已配置的备用模型。
- 普通 `Throttling.RateQuota` 仍按瞬时故障处理，不会停用模型。
- 管理后台已有模型测试、启用和停用操作。

本次只补充持久化原因、后台状态展示和受控恢复，不新增调度系统。

## 数据模型

在 `models` 表增加两个可空字段：

```sql
disabled_reason TEXT NULL
disabled_at TEXT NULL
```

`disabled_reason` 当前只持久化系统故障原因：

- `quota_exhausted`：供应商明确返回额度耗尽、余额不足或欠费。
- `NULL`：模型正常，或由管理员普通停用。

不新增故障历史表。当前需求只需要模型的现时可用状态；如果未来需要审计多次故障，再增加独立事件表。

迁移必须可重复执行，旧数据默认两个字段均为 `NULL`。

## 后端行为

### 自动停用

`disableQuotaExhaustedModel()` 识别到明确额度错误后：

1. 将模型 ID 加入进程内禁用集合，防止并发请求继续调用。
2. 在一次数据库更新中写入：
   - `enabled = 0`
   - `disabled_reason = 'quota_exhausted'`
   - `disabled_at = CURRENT_TIMESTAMP`
3. 保留供应商错误日志。
4. 将当前调用交给现有备用模型链路。

如果备用模型也返回明确额度错误，对备用模型执行相同停用和标记；随后沿用现有规则级兜底。

### 不自动停用的错误

以下情况不得写入额度耗尽标记：

- 普通请求频率限制。
- 网络超时或连接失败。
- 服务端 5xx。
- 无效请求、上下文过长或内容安全错误。
- 空响应或响应格式错误。

### 管理员停用

管理员主动关闭模型时：

- 写入 `enabled = 0`。
- 清空 `disabled_reason` 和 `disabled_at`。
- 后台显示“已停用”，不显示“额度已用完”。

### 手动恢复

后台重新启用额度耗尽模型时采用现有接口组合：

1. 调用现有模型连接测试接口。
2. 测试失败：保持停用和原标记，展示供应商错误。
3. 测试成功：调用现有模型更新接口设置 `enabled = true`。
4. 后端在启用成功时清空 `disabled_reason`、`disabled_at` 和进程内禁用集合。

不新增专用恢复接口。测试与更新之间的短暂时间差可接受；如果模型随后再次耗尽，实际调用会重新标记。

## API 与类型

现有模型读取接口增加两个兼容字段：

```ts
disabledReason: 'quota_exhausted' | null;
disabledAt: string | null;
```

数据库行类型使用蛇形字段：

```ts
disabled_reason: string | null;
disabled_at: string | null;
```

不改变玩家配置、游戏 REST API、WebSocket 事件、公开快照或模型实际调用 ID。

## 管理后台

模型列表按以下优先级展示状态：

1. `disabledReason === 'quota_exhausted'`：红色“额度已用完”，并显示停用时间。
2. `enabled === false`：普通“已停用”。
3. `enabled === true`：现有启用状态。

对额度耗尽模型点击启用时：

- 按钮进入测试状态，防止重复提交。
- 测试成功后完成启用并刷新列表。
- 测试失败时保持红色标记并显示错误消息。

不增加额度进度条或剩余 Token 数，避免展示无法可靠获取的数据。

## 错误处理与一致性

- 进程内禁用集合先更新，数据库持久化随后执行，优先阻止继续消耗或扣费。
- 数据库写入失败必须记录错误，不返回假成功；当前请求仍可尝试备用模型。
- 服务重启后以数据库 `enabled = 0` 为准，不会重新调度已耗尽模型。
- 管理员重新启用时清理进程内标记，确保恢复立即生效。

## 验证

至少覆盖：

1. 主模型额度耗尽后持久化标记，并返回备用模型结果。
2. 备用模型额度耗尽后也被持久化标记。
3. 普通 429 不停用、不标记模型。
4. 网络、5xx 和格式错误不写入额度标记。
5. 服务重启后数据库中的禁用状态仍阻止调度。
6. 管理员普通停用不显示额度耗尽。
7. 测试失败时不能重新启用。
8. 测试成功并启用后清除数据库和内存标记。
9. 数据库迁移重复执行不报错。

验证命令包括目标单元测试、迁移测试、服务端和管理端类型检查与构建。

## 影响范围

- 后端：模型仓储、模型服务、LLM 错误处理。
- 数据库：`models` 表新增两个可空字段。
- 管理后台：模型状态展示和重新启用交互。
- 共享类型：模型 API 与数据库行类型。
- 文档：同步更新服务端和管理后台项目说明。

## 明确不做

- 不轮询供应商剩余额度。
- 不抓取或模拟登录供应商控制台。
- 不按本地 Token 计数推算免费额度。
- 不增加全局随机模型池。
- 不自动重新启用模型。
- 不改变每个玩家只配置一个备用模型的现有规则。
