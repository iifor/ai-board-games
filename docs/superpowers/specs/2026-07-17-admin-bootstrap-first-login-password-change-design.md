# 管理员首次登录强制改密设计

## 目标

部署者在首次部署时通过 `.env` 设置初始管理员密码。系统仅在管理员表为空时创建该账号；首次登录后必须修改密码，修改前不能访问其他管理接口。

## 初始化规则

- `JWT_SECRET` 在生产环境仍为必填，长度至少 32 个字符。
- `.env` 中配置 `ADMIN_USERNAME=admin` 与 `ADMIN_PASSWORD`（至少 12 个字符）。
- 仅当 `admin_users` 没有任何记录时，创建该账号，并标记为 `must_change_password=1`。
- 已有任意管理员时跳过初始化，不创建、禁用、更新或覆盖任何账号；环境变量也不会重置旧密码。

## 认证流程

1. 登录成功的响应包含 `mustChangePassword`。
2. 标记用户的 JWT 只能访问 `POST /api/admin/auth/change-password` 和读取当前身份的接口。
3. 其他管理 API 返回明确的“请先修改初始密码”错误。
4. 改密接口验证当前登录用户、校验新密码摘要格式、更新密码哈希并清除标记。
5. 改密成功后签发新 JWT，管理端进入仪表盘。

## 实现范围

- SQLite 迁移为 `admin_users` 增加持久化改密标记。
- 复用现有 `auth` 模块的配置、初始化、仓储、控制器、路由和中间件。
- 管理端复用 `adminApi` 的令牌存储，新增加密页面和路由守卫。
- 更新部署与管理端文档，并补充初始化、强制改密和已有账号不覆盖的测试。

## 非目标

- 不新增账号找回、邮件通知、多管理员管理或第三方身份认证。
- 不改动 C 端、游戏流程或公开 WebSocket 协议。
