# 灯影预言家 12 人模式设计

日期：2026-07-23
状态：已确认

## 目标

在现有狼人杀工作流中新增官狼“灯影预言家”12 人模式，同时保持服务端权威裁决、玩家信息隔离和现有播放/回放管线。

模式 ID：`shadow-seer-12`

阵容：

- 狼人阵营：`werewolf` × 3、`wolf_king` × 1
- 神职：`seer`、`witch`、`guard`、`knight`
- 民职：`villager` × 3、`shadow_seer` × 1

`shadow_seer` 属于好人阵营，按民职参与屠边判定。

## 明确不做

- 不指定狼人悍跳人选。
- 不强制狼人报名竞选警长。
- 不要求出现两个狼预，也不限制狼人跳预数量。
- 不增加上警、悍跳、报验人或真假预判断策略提示。
- 不复制一套灯影预专用工作流。
- 不新增数据库表、REST API 或 WebSocket 控制协议。

所有玩家依据公开规则和各自私有信息自由决策。服务器只负责身份、合法行动、查验结果、信息可见性和胜负裁决。

## 身份模型

服务端在真实状态中保存 `role: "shadow_seer"`，上帝视角、调试审计和赛后记录可以显示“灯影预言家”。

灯影预玩家的私有身份视图必须与普通预言家一致：

- 身份名称为“预言家”。
- 角色责任、能力和可执行动作与普通预言家一致。
- 系统提示、玩家记忆、技能入口和玩家视角不得出现 `shadow_seer` 或“灯影预言家”。
- 公开模式说明可以包含板型中同时存在预言家和灯影预言家，这是所有玩家都知道的公共规则。

身份遮蔽只发生在构建玩家私有角色视图的边界。真实角色仍保留在服务端 Agent、状态快照和胜负逻辑中，避免用模糊状态驱动规则。

## 夜间查验

`seer` 和 `shadow_seer` 都复用现有 `inspectFaction` 动作与 `seer_check` 夜间步骤。

现有 actor 选择从“取第一个具备 `inspectFaction` 的角色”调整为“取全部存活且具备该动作的角色”。其他模式只有一名查验者，因此行为不变。

两名查验者在同一夜独立选择目标：

- 普通预言家：目标为好人时得到“好人”，目标为狼人时得到“狼人”。
- 灯影预言家：目标为好人时得到“狼人”，目标为狼人时得到“好人”。
- 两者都不能查验自己，并继续遵守现有目标合法性规则。

查验结果必须由服务端根据真实 actor、真实目标和目标阵营计算，不信任模型返回的阵营结果。AI 只负责选择合法目标及可选原因。

## 多查验状态

当前单条 `round.night.seerCheck` 不能表达同夜两名查验者。新增可选集合：

```ts
round.night.seerChecks: Array<{
  actorId: number;
  target: number;
  result: "好人" | "狼人" | "无法验出结果";
  reason?: string | null;
}>;
```

每名玩家自己的 `player.seerChecks` 仍只保存该玩家获得的结果。

兼容策略：

- 单查验者模式继续维护现有 `round.night.seerCheck`。
- 多查验者模式以 `round.night.seerChecks` 为准，不用后一个结果覆盖前一个结果。
- 现有单预言家事件和客户端读取路径保持兼容。

## 私密频道与投影

每份查验结果使用 `player:<actorId>` 私密 scope，不再依赖会让同类角色共享信息的 `scope:seer`。

- 查验者只能收到自己的目标和结果。
- 两名预言家互相看不到对方身份、目标、结果和私有历史。
- 通用“预言家请睁眼/闭眼”阶段展示不携带 actor 列表或查验结果。
- 上帝视角可以投影全部 `seerChecks`。
- 玩家视角只投影 viewer 自己的查验记录。
- 公共实时事件和公共回放不得包含任何私密查验结果。

`seer_checked`、阶段结果、Trace 反馈和相关投影都必须带明确的 `actorId`，以便执行相同动作的两个玩家仍能独立路由和审计。

## 既有规则复用

模式直接复用：

- 狼队夜聊、刀人和自由战术决策
- 狼王死亡技能与统一死亡链
- 骑士决斗
- 女巫、守卫
- 警长报名、发言、退水、投票和警徽流
- 白天发言、放逐、遗言、胜负和赛后流程
- TTS、ACK、暂停/继续、实时播放和历史回放

灯影预死亡按民职死亡统计；其存在不阻止屠神胜利。

## 展示

- 模式选择器和管理端显示“灯影预言家（12人）”。
- 上帝视角显示真实“灯影预言家”角色。
- 玩家视角和该 AI 玩家的私有上下文显示“预言家”。
- 查验展示沿用现有预言家交互，不新增专用玩法 UI。
- 调试模式仍走相同 reducer、effect、channel 和 projection；只用合法随机目标替代真实模型调用。

## 影响范围

- 服务端：角色/模式配置、玩家私有身份构建、查验 actor 选择、结果裁决、状态投影和私密事件路由。
- 共享类型：为多查验记录和 `actorId` 增加向后兼容的可选字段。
- 客户端：兼容单条与多条查验状态，并按 viewer 只展示自己的结果。
- 管理端：通过现有角色和模式配置管理能力展示新条目。
- 文档：同步狼人杀工作流、服务端、共享类型、客户端和管理端说明。
- 数据库：无 schema 变化，仅由现有 seed/upsert 写入新角色和模式配置。

## 错误处理

- actor 已死亡、无合法目标或动作被现有禁用规则阻止时，沿用当前跳过逻辑。
- 模型返回非法目标时，沿用现有校验和安全兜底；模型返回的阵营结果一律忽略。
- 缺少 `actorId` 的旧查验事件继续走单预言家兼容路径。
- 多查验结果不得降级为共享 `seer` scope；无法确定 actor 时应记录 invariant/Trace 错误，而不是公开结果。

## 验证

最小验收集合：

1. 新模式包含准确的 12 人阵容，`shadow_seer` 为 good/villager。
2. 灯影预玩家的系统提示、角色能力和私有视图只显示“预言家”。
3. 普通预言家得到真实阵营；灯影预得到相反阵营。
4. 同夜两份查验均被保存，不互相覆盖。
5. 两份结果分别路由到对应 `player:<actorId>`，不能跨玩家访问。
6. 上帝视角可见全部结果，玩家视角和公共回放不泄露其他结果。
7. 警长报名和发言没有新增策略约束，狼人可自由决定是否悍跳。
8. 灯影预按民职参与屠边判定。
9. 标准单预言家模式的状态、事件和展示保持不变。
10. 调试模式完成至少一夜双查验流程。
