# 全身玩家透明立绘设计规格

## 目标

将 `packages/client/public/player-poster-cutouts/` 下现有 13 位玩家立绘统一为头顶到鞋底完整入镜的透明全身图。保留现有人物身份识别，不修改文件映射、组件、接口、数据库、工作流或共享类型。

## 方案

逐张以现有 cutout 为编辑目标，向下扩展缺失的裤腿和鞋子。每张图片独立生成，避免批量拼图裁切造成比例、身份或透明边缘不一致。

### 必须保持

- 脸型、五官、肤色、发型和发色
- 上衣、配色、图案、配饰和整体人物画风
- 玩家与现有文件名的一一对应关系
- 正面自然站姿和原有年龄感

### 只允许改变

- 补全缺失的下半身、裤腿和鞋子
- 为完整全身构图适度缩小主体
- 调整手臂或腿部姿势，使站姿自然且不遮挡身体轮廓
- 清理原图截断边缘和透明底残留

## 统一输出标准

- 画布：竖版 2:3
- 取景：头顶、双手、双腿和鞋底全部可见
- 边距：头顶和鞋底均保留透明安全边距，人物不贴边
- 对齐：人物水平居中，鞋底位于统一基线附近
- 背景：最终必须为透明背景，无舞台、房间、地面、阴影、光斑或文字
- 边缘：头发和服装边缘无明显色边、白边或锯齿
- 格式：保留现有 `.webp` 文件名和 alpha 通道

## 生成与透明处理

使用内置图像编辑逐张保持身份并扩展全身。编辑源先输出到与人物颜色不冲突的纯色键控背景，再通过已安装的 `remove_chroma_key.py` 转为透明 WebP。

- 默认键控色使用纯绿色；绿色服装或配饰明显的角色改用纯洋红色。
- 中间文件放入 `tmp/imagegen/`，验证通过后才替换项目中的同名 cutout。
- 现有文件受 Git 保护，不额外创建运行时备份目录。

## 验收

1. 13 个既有文件名全部存在，没有新增或缺失玩家。
2. 每张图片具有 alpha 通道，四角透明，无键控色残留。
3. 每张人物从头顶到鞋底完整可见，主体不贴边、不被画布裁切。
4. 人脸、发型、上衣和关键配饰与对应原图可识别为同一人物。
5. 在辩论 v2 的 1280 × 720 发言态中，人物完整显示且不与阶段标题、评委和字幕重叠。
6. `playerPosterSpotlight` 单元测试、客户端类型检查和客户端构建通过。

## 失败处理

- 身份或服装漂移：只针对该角色重新编辑，不降低其他已通过素材。
- 透明边缘有色边：调整键控色或重新运行去色边处理。
- 鞋子、手指或腿部异常：重新生成该角色，不用裁切掩盖。
- 内置透明处理无法稳定保留头发边缘时，停止并征求是否改用需要 API Key 的原生透明 CLI 路径。
