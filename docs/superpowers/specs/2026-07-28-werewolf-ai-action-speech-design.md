# 狼人杀行动结果改为角色自然台词

## 目标

将当前 28 个“服务端固定行动结果 + 大模型 `reason`”场景改为由行动角色直接生成完整、自然的第一人称台词。服务端继续裁决行动是否生效及真实目标，大模型台词不参与规则判定。

示例：

- 解药：`我决定救下7号，他很可能是关键神职，现在还不能倒下。`
- 毒药：`我今晚选择毒掉5号，他的发言和投票明显矛盾，我认为他很可能是狼人。`

不再播报 `女巫使用了解药。<原因>`、`女巫毒了5号。<原因>` 这类服务端拼接文本。

## 范围

- 覆盖 `actionPhases.ts` 当前通过 `withReason()` 生成结果的全部 28 个行动。
- 覆盖当前实时流程、旁白兜底和旧回放重建，避免同一行动在不同入口恢复固定前缀。
- 保持现有事件可见范围，私密行动不会因此变成公开信息。
- 不调整 C 端布局、WebSocket 协议、REST API、数据库或游戏规则。
- 不处理“请睁眼”“请闭眼”“未使用技能”“空守”等没有拼接模型原因的规则提示。

## 两类生成方式

### 决策时已知结果的 24 个行动

女巫解药、女巫毒药、守卫守护等行动在模型作出选择时已经知道行动及目标，继续复用本次行动调用生成完整台词，不增加模型请求。

### 服务端结算后才知道结果的 4 个行动

以下结果无法由模型在决策时提前知道：

- 预言家查验：好人或狼人。
- 幸运儿查验：具体查验结果。
- 狐狸查验：三连中有狼或无狼。
- 黑商赠技：成功或失败。

这 4 个行动先由服务端完成规则结算，再使用同一角色模型增加一次简短结果表达调用。调用上下文包含服务端真实结果和模型此前选择目标的原因，只生成一句可直接播报的第一人称台词。该调用不改变已经生效的行动结果。

## 模型输出契约

继续复用现有结构化行动字段：

```json
{
  "use": true,
  "targetSeat": 5,
  "reason": "我今晚选择毒掉5号，他的发言和投票明显矛盾，我认为他很可能是狼人。"
}
```

- `use`、`targetSeat` 等结构化字段是服务端唯一可信的行动事实。
- 对 24 个决策型行动，`reason` 改为可直接播报的完整角色台词，不新增共享 `speech` 字段。
- 行动生效时 `reason` 必须是非空字符串；模型缺失时沿用现有纠正、重试和游戏级兜底机制。
- 台词使用第一人称，说明选择及依据，并在涉及目标时使用本次结构化目标。
- 台词只能引用角色已知信息，不得泄露未公开身份或把推测表达为系统事实。
- 台词保持简短，沿用现有长度限制，不生成 Markdown 或额外解释。
- 对 4 个结果型行动，第二次调用只返回一句纯文本台词；服务端把真实结算结果明确提供给模型，不接受模型修改目标或结果。

## 数据流

1. 现有行动提示词向模型提供合法目标、公开事实、角色私密信息和本次任务。
2. 模型返回结构化行动；24 个决策型行动同时返回完整角色台词。
3. reducer 继续校验并应用 `use`、`targetSeat` 等行动字段。
4. 4 个结果型行动在服务端结算后，使用同一角色模型生成包含真实结果的自然台词。
5. 行动结果事件直接使用规范化后的角色台词作为展示及 `speakableText`，不再调用 `withReason()` 添加固定结果前缀。
6. C 端继续消费现有 `presentation.speakableText`，无需新增组件或状态。

## 兼容与失败处理

- AI 成功行动必须生成完整台词；决策调用缺失或空台词按无效模型输出处理。
- 结果型行动的第二次调用失败时，使用服务端确定性结果作为降级反馈，不能阻塞游戏流程。
- 人类玩家、调试随机行动或最终游戏级兜底没有模型台词时，保留确定性的行动反馈，避免流程无声或无法确认结果。
- 旧事件中已经保存的完整历史文案保持可回放；仅旧结构重建时停止重新添加固定前缀。
- 决策型台词与结构化目标冲突时，以结构化行动结果为准，并记录为无效输出进入现有纠正路径。
- 结果型台词仅用于展示和播报，服务端结算结果始终是唯一真实来源。

## 验证

- 提示词测试：女巫解药、女巫毒药及通用目标行动要求生效时返回完整第一人称台词。
- 服务端单元测试：有 `reason` 时结果只包含模型台词，不含固定行动前缀。
- 结果表达测试：4 个结果型行动只在结算后调用模型，并把服务端真实结果传入提示词。
- 降级测试：结果表达调用失败时使用确定性结果且工作流继续推进。
- 校验测试：行动生效但台词为空、目标与台词冲突时不能作为合格 AI 输出。
- 回放测试：实时事件、旁白兜底和旧结构重建不会重新拼接固定前缀。
- 回归测试：行动目标、技能消耗、可见范围、TTS/ACK 流程及游戏结算不变。

## 非目标

- 不让模型决定服务端规则结果。
- 除 4 个结果型行动各一次结算后表达调用外，不增加其他模型请求。
- 不增加新的配置项或第三方依赖。
- 不重构无关行动阶段或 C 端舞台组件。
