# 谁是卧底 v2 大屏观战舞台设计

## 目标

将 `/game/v2/undercover` 重构为 16:9 大屏观战优先的“环形推理剧场”。观众应在一秒内识别当前阶段、发言者、字幕和其他玩家状态，同时消除当前页面重复展示发言者、海报遮挡信息和席位层级混乱的问题。

本次只改变客户端的布局、视觉状态和交互表达。服务端事件、WebSocket、TTS、ACK、回放、游戏规则、API、数据库和共享类型保持不变。

## 第一性设计结论

舞台只有一个主角。当前发言者在中央以完整人物海报呈现，姓名和“正在发言”只出现一次；其余五名玩家与当前玩家的席位固定分布在环形舞台周围，通过亮度、描边和文字状态表达变化，不通过重复卡片抢夺注意力。

## 页面结构

从上到下分为五层：

1. **阶段 HUD**：居中显示轮次、阶段名称和当前进度。它是紧凑导航信息，不承担玩家状态展示。
2. **环形席位**：六个紧凑席位固定在椭圆舞台周围，始终位于安全边距内。席位包含号码、头像或品牌图标、名称和文字状态。
3. **中央聚光区**：发言阶段显示当前玩家的完整人物海报；其他阶段复用同一区域显示现有准备、投票或结算内容。
4. **字幕下三分之一**：显示当前公开发言文本，下面以弱层级显示下一位玩家提示。
5. **控制栏**：底部居中的紧凑工具栏，保留返回、暂停或继续、语音开关，以及回放模式下的跳过控制。

页面不再显示左上角孤立状态提示、独立底部发言者标签或覆盖在海报上的第二张发言者卡片。

## 布局规则

- 设计基准为 1920×1080，舞台保持 16:9。
- 主内容最大宽度受视口限制并水平居中；21:9 屏幕增加两侧留白，不拉伸席位间距。
- 六个席位使用固定的环形位置，阶段切换、淘汰和结算时不重新排序。
- 中央人物海报不得遮挡阶段 HUD、字幕或控制栏。
- 当前发言席位仍保留在环形位置，仅以强调描边和“发言中”状态与中央海报关联，不再复制大型卡片。
- 低于桌面观战宽度时使用 CSS 缩放和紧凑间距保证六席可见；不新增移动端专用交互或 JavaScript 布局逻辑。
- 经典 `/games/undercover` 页面保持现状；新布局仅在 v2 海报舞台启用。

## 状态与交互

### 准备阶段

中央区域显示现有规则或开场信息。六个席位保持稳定，状态使用“准备中”或现有公开状态，不显示人物海报。

### 依次发言

- 中央只显示当前发言者的人物海报、姓名和“正在发言”。
- 环形中的对应席位使用洋红色聚光描边，并显示“发言中”；其他存活席位降低视觉权重。
- 字幕区显示现有公开发言文本，下一位提示位于字幕下方。
- 发言者切换时，旧海报淡出，新海报淡入；不重启动画之外的播放、TTS 或 ACK 行为。

### 投票阶段

中央聚光区切换为现有投票提示或公开结果，不显示人物海报。席位仅展示服务端公开状态和公开票数；客户端不推断合法投票、秘密身份或未公开票型。

### 淘汰状态

被淘汰席位保持原位置，降低饱和度和亮度，并同时显示“已淘汰”文字。状态不能只依赖颜色表达。

### 结束阶段

中央区域展示现有公开结算、词语和身份揭晓信息。六个席位继续保留，使用公开结果标记身份或胜负；客户端不从未公开状态自行推断结论。

### 回放

回放与实时模式消费相同的最终展示状态。视觉切换不得改变事件顺序、重新计算游戏结果或读取秘密原始状态。

## 视觉系统

- 背景：深海军蓝到蓝紫色渐变，保留低对比度舞台环和少量粒子。
- 主强调色：受控的洋红色，仅用于当前发言者、进度重点和关键状态。
- 存活状态：绿色文字配合明确标签；淘汰状态：灰白文字和去色处理。
- 中央海报是唯一高面积、高对比度内容；席位、HUD 和控制栏均降低面积与光晕强度。
- 正文和字幕保证大屏远距离可读，不使用细字重或低对比度灰色承载关键信息。

## 动效与可访问性

- 发言者切换使用 200–300ms 的透明度和轻微缩放过渡。
- 席位状态使用描边、亮度和文字同步变化，不使用位移重排。
- `prefers-reduced-motion: reduce` 下取消缩放和位移动画，只保留即时或极短透明度切换。
- 控制按钮保留可见键盘焦点、可读标签和现有可操作区域。
- 发言状态和淘汰状态必须包含文字，不依赖颜色、光晕或音频。
- 字幕继续使用现有可读文本语义；视觉装饰图片不增加重复朗读内容。

## 组件边界

优先复用现有模块，不引入依赖：

- `UndercoverGame`：继续负责页面组合、状态提示和控制区挂载。
- `UndercoverArena`：负责阶段 HUD、固定环形席位、中央阶段内容和字幕层级。
- `PlayerPosterSpotlight`：继续解析并展示人物海报，但在谁是卧底 v2 中只承担中央海报视觉，不再重复渲染独立发言者标签。
- `UndercoverControls`：保留现有行为，只压缩视觉尺寸和层级。

复杂游戏状态、网络请求、播放控制和规则判断不得移动到这些展示组件中。

## 错误与降级

- 当前玩家不存在、`playerId` 无效或海报加载失败时，中央区域回退到现有头像或阶段内容，游戏继续运行。
- 没有公开字幕时保留稳定字幕区域或现有空状态，避免舞台跳动。
- 没有下一位玩家时不渲染下一位提示，不使用占位文案制造错误信息。
- 海报和视觉动画失败不得阻塞字幕、TTS、播放推进或 ACK。

## 验收标准

- 1920×1080 下六个席位、阶段 HUD、完整中央海报、字幕和控制栏同时可见且互不遮挡。
- 当前发言者只存在一个主视觉和一处主姓名标签，不再出现大型重复卡片或独立底部重复标签。
- 准备、发言、投票、淘汰、结束和回放状态均复用同一舞台坐标，不发生席位重排。
- 经典页面视觉不变；v2 实时和回放行为一致。
- 客户端不新增秘密身份、词语、票型、胜负或合法性推断。
- 海报加载失败与缺失公开数据时可安全降级，游戏流程不受影响。
- 键盘焦点、文字状态、对比度和 reduced-motion 行为有效。
- 相关单元测试、客户端类型检查和生产构建通过。

## 明确不做

- 不增加自动隐藏控制栏、导演模式、镜头切换器或观众互动。
- 不新增移动端专用布局系统。
- 不新增服务端事件、字段、API、数据库表、依赖或设计系统。
- 不重构其他 v2 游戏页面，也不修改人物海报资产生成流程。
