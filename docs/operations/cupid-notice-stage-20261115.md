# 丘比特情侣通知仅保留在后台

`cupid_bond` 阶段向情侣双方发出的私密 narration 不再进入前台播放流。相关文字继续保存在后台日志和玩家的 `seatNotes` 私密认知中，AI 玩家仍能获知配对座号与殉情规则。游戏规则函数和 GameSpec hash 没有改动。

播放流在上帝及玩家视角下都跳过此类通知，自动确认其序号并继续推送后续事件；语音预取同样跳过，因此前台不会朗读或显示这条通知的字幕、记录和技能反馈。实时与已有回放共用过滤。丘比特连线动作、已知情侣状态图标、其他私讯和公开播报保持原有处理。

## 文件职责

- 修改 `packages/server/src/modules/realtime/perspective.ts`：增加针对情侣私讯的舞台可见性规则。
- 修改 `packages/server/src/modules/realtime/session.ts`：发送及语音预取复用规则，跳过时沿用自动确认机制。
- 新增 `packages/server/test/realtimeStageNotices.test.ts`：覆盖过滤范围、两个视角、实时与回放、跳过通知的语音及进度确认。
- 修改 `docs/project-server.md`、`docs/project-client.md`：记录后台私密认知和前台展示的区别。
- 新增本文：变更和验证记录。

没有删除文件；无前端组件、数据库、共享类型或 API 消息结构改动。WebSocket 的展示事件范围按上述规则收窄。

## 验证

服务端 TypeScript 检查通过。实时流单元测试、新增通知测试和丘比特板子规则测试共 3 个文件、21 项测试通过。已验证跳过两个情侣通知后仍发送后续事件，不调用通知对应的音频解析（包括已有缓存音频场景），也不删除后台事件。

当前复用现有播放投影模块，无需进一步拆分或新增依赖。
