# 配置迁移

适用于把本地配置迁入首次部署的空库。导出、导入使用同一版代码。在项目根目录安装依赖后执行。

## 迁移范围

| 配置 | 迁移内容 |
| --- | --- |
| 模型供应商 | 名称、地址、加密 API Key、启用状态 |
| 模型 | 模型 ID、参数、备用模型关系、启用状态及停用原因 |
| 音色 | 来源、音色名、语言、性别、风格、语速、音调、试听文本及说明 |
| 玩家 | 昵称、立绘标识、头像地址、人设、模型及音色绑定、温度、预算、篇幅和启用状态 |
| 视角管理 | 自定义叫号、法官播报、私密行动提示词 |
| 提示词管理 | 目录模板、修订号、已应用的板子模板与人设覆盖、发布优先级 |

内置模板随代码部署，数据库中保存的自定义版本随迁移包导入。保留配置 ID。模板发布顺序保留，目录模板和板子模板的覆盖关系与本地一致。

历史对局、回放、调用链、提示词实验、玩家记忆、复盘队列、音频缓存和管理员账号均不在文件中。板子模板仍可生效，其来源实验编号置为 0，表示没有对应的线上实验。新库玩家记忆清空批次从 0 开始。创建和更新时间由目标数据库生成。

头像字段迁移其地址。若地址仅能在本地访问，需要换成线上可访问的地址；内置立绘随代码部署。

## 本地导出

根目录 `.env` 中的 `DATABASE_URL` / `DATABASE_SCHEMA` 指向本地数据库，`SECRET_KEY` 使用本地现有值。

```sh
pnpm config:export --file artifacts/config.enc
```

导出在同一只读快照中读取配置。文件采用 AES-256-GCM 整体加密，同时保留供应商密文；使用本地 `SECRET_KEY` 解包。脚本检查供应商密钥是否可解密，只输出各类配置数量，不输出密钥、提示词或人设正文。目标文件已存在时退出，重新导出请换文件名或手动处理旧文件。

将 `artifacts/config.enc` 传至服务器。解包用的源 `SECRET_KEY` 通过部署环境变量单独配置，包内不包含解密密钥。`artifacts/` 已在 Git 忽略范围内。

## 线上导入

在服务器的项目根目录执行。环境变量优先于根目录 `.env`。

1. 配置线上 `DATABASE_URL`、可选的 `DATABASE_SCHEMA`（默认 public）及目标 `SECRET_KEY`。
2. 若目标 `SECRET_KEY` 与本地相同，直接导入。
3. 若目标密钥不同，把本地密钥放入 `CONFIG_SOURCE_SECRET_KEY` 环境变量，再导入。

```sh
pnpm config:import --file artifacts/config.enc
```

脚本校验解密和文件格式后自动执行当前代码的数据库迁移，再导入配置。可以在首次启动服务端之前执行，无需配置 JWT 或管理员凭证。服务端随后启动时按线上 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 创建管理员。

供应商 API Key 会用目标 `SECRET_KEY` 重新加密。因此线上可使用独立密钥。完成后可移除 `CONFIG_SOURCE_SECRET_KEY`。

Azure 和 MiMo 的凭证从环境变量读取，需单独设置 `AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`、`MIMO_API_KEY` 及适用的服务地址。它们不进入数据库配置包。

## 一致性与验证

- 目标配置表和对局表必须为空。已有管理员账号可以保留。重复导入会明确失败，已有配置不被覆盖。
- 所有配置写入和序列重启在同一个事务中完成，失败全部回滚。模型先写入，再恢复备用模型关系，支持正向和循环引用。
- 导入锁定目标配置表及对局表，防止与另一份导入或后台写入交错。导入后校正供应商、模型、音色、玩家 ID 序列，以及模板发布序列。
- 导入成功后核对终端数量，进入后台检查玩家绑定、提示词和播报，再用模型测试、音色试听验证线上供应商连接。
- 文件格式为 `AT-ODDS-CONFIG-1`，包内容另有版本号与导出时间。不支持的版本和缺失关联会在写入前被拒绝。
- 查看帮助使用 `pnpm config:export --help` 或 `pnpm config:import --help`。
